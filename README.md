# Командный Telegram-бот

Бот слушает групповой чат, сохраняет текстовые сообщения в Pinecone с помощью пайплайна Haystack, подводит итоги обсуждений и отвечает, когда его позвали. Для ответов он ищет релевантные сообщения по смыслу и учитывает недавний контекст чата.

## Как это работает

В `PipelineManager` создаются три пайплайна Haystack:

1. **Индексация:** `OpenAIDocumentEmbedder` превращает сообщение в вектор, затем `DocumentWriter` записывает документ в `PineconeDocumentStore`. Компоненты соединены выходом `embedder.documents` со входом `writer.documents`; при совпадении документа используется политика `OVERWRITE`.
2. **Поиск:** `OpenAITextEmbedder` превращает запрос в вектор, а `PineconeEmbeddingRetriever` ищет похожие документы. Вход `text_embedder.embedding` соединён с `retriever.query_embedding`. Поиск фильтруется по `chat_id`; `top_k` установлен в 30.
3. **Суммаризация и ответы:** `ChatPromptBuilder` формирует сообщения для модели из режима, вопроса и контекста, а `OpenAIChatGenerator` генерирует текст. Выход `prompt_builder.prompt` соединён со входом `chat_generator.messages`. Системная инструкция требует отвечать по-русски и опираться только на переданный контекст.

Каждое входящее текстовое сообщение от человека, не являющееся командой, индексируется, кроме сообщений, адресованных боту в группе: упоминаний бота или ответов на его сообщение. Команды и сообщения от ботов не индексируются. Бот отвечает на обычный текст в личном чате; в группе отвечает, если его упомянули по `@username` (в том числе через сущность Telegram `text_mention`) или если сообщение является ответом на сообщение бота.

В метаданные документа записываются `author_name`, `author_id`, `chat_id`, `message_id` и `timestamp`; `username` добавляется, если он есть у автора. Имя формируется из `first_name` и `last_name` профиля Telegram, а если их нет, используется ID автора. Время переводится в ISO-формат UTC.

Для ответа бот ищет до 30 документов в текущем чате, затем объединяет найденные сообщения с последними 15 сообщениями из памяти процесса. Текущее сообщение и дубликаты по ID исключаются, контекст сортируется по времени. В prompt передаются автор, время и текст; если доступен username, он также указывается. Ответ на вопрос просит приводить ссылки на сообщения в формате `[автор, время]`.

Команды `/start_listening` и `/stop_listening` управляют отдельной сессией обсуждения для чата. Во время сессии бот добавляет в неё текстовые сообщения людей. `/stop_listening` формирует итог по собранным сообщениям; если сессия пуста или не запущена, бот сообщает об этом.

## Команды и сценарии

- `/start` — кратко сообщает о назначении бота и командах сессии.
- `/start_listening` — начинает собирать сообщения для итога в текущем чате; повторный вызов начинает список сессии заново.
- `/stop_listening` — завершает текущую сессию и отправляет её итог.
- `@username` — упоминание бота в групповом сообщении запускает ответ на текст без упоминания.
- Ответ на сообщение бота — запускает ответ с учётом текста ответа.
- Личный чат — бот обрабатывает каждое текстовое сообщение пользователя, кроме команд.

## Структура проекта

- `bot.py` — обработчики Telegram-команд и сообщений, управление сессиями, выбор повода для ответа и сбор контекста.
- `config.py` — загрузка обязательных настроек из окружения и `.env`.
- `pipelines.py` — Pinecone document store, три пайплайна Haystack, индексация, поиск, генерация ответа и форматирование времени.
- `logging_setup.py` — настройка логирования в консоль и `bot.log`.
- `requirements.txt` — закреплённые версии зависимостей Python.
- `.env.example` — шаблон имён настроек без действующих ключей.
- `.gitignore` — исключения Git, включая `.env` и `.venv/`.
- `pipeline_example.ipynb` — образец из tutorial Haystack Extractive QA: загрузка набора Seven Wonders, индексация в `InMemoryDocumentStore`, поиск по эмбеддингам и извлечение ответа через `TransformersExtractiveReader`. Это отдельный учебный пример, а не пайплайн Telegram-бота.

## Установка и запуск

1. Установите Python 3.11.
2. В PowerShell из корня проекта создайте и активируйте виртуальное окружение:

   ```powershell
   py -3.11 -m venv .venv
   .\.venv\Scripts\Activate.ps1
   ```

3. Установите зависимости:

   ```powershell
   python -m pip install -r requirements.txt
   ```

4. Создайте `.env` на основе шаблона и заполните значения локально:

   ```powershell
   Copy-Item .env.example .env
   ```

   Нужны настройки `TELEGRAM_BOT_TOKEN`, `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `OPENAI_MODEL`, `EMBEDDING_MODEL`, `PINECONE_API_KEY`, `PINECONE_INDEX_NAME` и `PINECONE_NAMESPACE`. Для Pinecone в коде задана размерность векторов 1536.

5. Создайте бота через [BotFather](https://t.me/BotFather), получите токен и укажите его в `.env`. Чтобы бот получал обычные сообщения группы, откройте в BotFather `/setprivacy`, выберите бота и установите `Disable`.
6. Запустите бота:

   ```powershell
   python bot.py
   ```

7. Добавьте созданного бота в нужную Telegram-группу. Для ответов в группе упоминайте бота по username или отвечайте на сообщение бота.

## Безопасность

- Храните реальные токены и ключи только в локальном `.env`; не помещайте их в README, исходный код или коммиты.
- `.env` и `.venv/` указаны в `.gitignore` и не должны коммититься.
- В `.env.example` приведены только имена настроек и учебные значения-заполнители, не реальные ключи.

## Известные ограничения

- Поиск возвращает до 30 ближайших по смыслу сообщений чата. В небольших чатах это почти вся переписка, а в длинных часть сообщений (особенно очень коротких реплик) может не попасть в контекст ответа.
- Последние 15 сообщений хранятся только в памяти процесса и пропадают после перезапуска.
- Время в ответах указывается в UTC.
- Имена авторов берутся из профиля Telegram, а не из контактов.
- Сохраняются только текстовые сообщения людей; обработка документов не реализована.
Общие вопросы без темы («Что думаешь?») бот лучше всего разбирает, когда в чате идёт одно свежее обсуждение. Если в переписке накопилось несколько разных тем, ответ может стать расплывчатым: бот видит всё сообщения чата и не знает, какая тема «текущая».
